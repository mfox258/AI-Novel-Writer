# 可信内置组件运行层（首批）

只从 `public.ts` 导入。纯 TS 契约由 `../contracts/public.ts` 提供；没有 React、Node 或 Electron 运行依赖。组合根显式传入已审查的组件函数与每组件能力绑定；没有文件扫描、动态加载、包安装、`trusted: true` 自认证或第三方代码执行。

`register(component, bindings)` 仅登记；`activate(ids?)` 校验全登记表的重复/缺失/环，按依赖拓扑准备请求闭包。全部准备成功才开放本批调用；失败撤销本批，已运行的无关组件保留。准备阶段不可调用能力。每次准备/关闭递增代次，旧上下文永久失效。注册元数据和绑定均复制，后续修改原对象不改变登记。

组件必须在取得临时资源后立即 `context.own(resource)`，资源仅为注册/监听器/句柄，不得包含作者数据、持久定义、资产或历史删除操作。每个组件资源逆序释放，组件按逆拓扑释放；清理失败继续执行其余清理并报告错误，不声称失败的 disposer 已成功释放。

`deactivate(id)` 默认遇到活动依赖方拒绝，状态保持原样；显式 `cascade` 停用其活动传递依赖方。所有入口先封闭、代次失效并标记在途取消，再开始清理。并发生命周期操作明确拒绝（不排队）。重复停用是空操作。

本小型 ABI 的在途等待上限为零：不等待不可控的能力 Promise，取消是协作标记，不承诺撤回外部效应。迟到返回被拒绝，不能通过旧上下文调用新代；宿主适配器必须在真实效应边界重验取消/代次、保存和核对外部结果。不能把这里的 `stale-result` 当作外部操作未发生或退款证明。组件及 disposer 应及时完成，本层没有对恶意/挂起代码实施抢占、超时或隔离。

能力只暴露具名 JSON 请求函数，不提供原始 db/fs/IPC 或宿主对象。`requestedCapabilities` 只是说明，不产生授权；实际能力来自组合根传入的绑定。本层是可信代码的生命周期协调器，不是 JS 安全沙箱，也不能阻止同进程可信组件自行导入全局能力。

真实 principal/scope/Grant、权限撤销执行、精确 executor/Schema/hash 绑定、预算、持久调用历史、结果核对、包锁/安装/升级与跨进程恢复尚不在范围。能力适配器的权限执行必须由宿主 application 接入后实现。本 ABI 不冒充规范 31/32/35/36 的全部候选协议；本实现依据规范 24 的资源责任及当前架构第 6 章划分登记、激活与停用。

测试：`vitest run --config src/platform/plugin-runtime/vitest.config.ts`。
